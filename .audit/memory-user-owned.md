# One user profile and compact settings

The user rejected the personal/mailbox split and the amount of settings chrome. The runtime now has one private fact owner, the authenticated or explicitly verified user. Mailbox IDs describe source evidence and the applicability of label rules. They never create a second memory owner or another settings list.

Keeping a generic owner target would preserve the rejected branch behind a smaller interface. Deleting the branch removes the ambiguity from capture, consolidation, chat tools, CRUD, context reads and deletion. Pstack's Model the Domain and Laziness Protocol led to that smaller design. Historical storage discriminators and ownerless mailbox records remain inert for the later contract release; no production data was assigned, deleted or migrated.

General preferences follow the user across inboxes. Label facts use mailbox-qualified concept keys and source metadata because label IDs belong to a mailbox. Correction aggregation and deletion also match the actor. Shared background work receives operational sender/domain history without borrowing a billing owner's personal profile. Explicit shared-mailbox interactions can inform only the acting user's profile. Private mailbox transfers retain their owner checks, and unattributed outgoing text cannot establish that user's voice.

Settings is one Memories page with live search, one add control and an options menu for automatic learning and deleting all facts. Each row contains the fact and its edit/delete menu. There are no scope selectors, category controls, source/date rows, per-category add buttons, per-mailbox progress panels or repeated explanations. The editor has one text box and preserves existing internal metadata. Long lists use one Load more control.
