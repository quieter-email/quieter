# AI memory

Quieter stores categorized plain-text facts about a user and mailbox. The system learns from mail content, authored writing, conversations and meaningful actions. It consolidates new evidence into existing concepts. It does not use embeddings or an external vector index.

## Ownership and authority

Personal facts belong to one user and can inform that user's work across accessible mailboxes. Mailbox knowledge belongs to one mailbox and is available only through its access checks. Shared-mailbox automation receives mailbox knowledge. A private mailbox's automation can also receive its verified owner's personal preferences. The organization billing identity never grants access to that person's profile.

Only the acting user's explicit statements can establish instructions. Sent mail is evidence of writing style and durable facts. Received mail, quoted text, forwarded correspondence and connector results are untrusted evidence. They cannot change permissions, create instructions or overwrite explicit preferences. Secrets, verification codes and financial identifiers are excluded from long-term memory.

## Facts and consolidation

Facts have a concise text body, category, concept key, source, confidence, importance, confirmation date, reinforcement count, optional expiry and optimistic version. Exact correspondent addresses distinguish a person's specific voice from general writing habits. The categories are identity, writing style, relationships, preferences, work, interests, activity and labeling.

The writer sees actual authored text, sentence structure, wording, greetings and sign-offs. Brief examples are allowed when they explain the user's voice. Quoted replies are stripped from authored samples. Draft evidence remains provisional. Generated replies, chat compose output and formatted dictation leave only scoped text fingerprints. Capture recognizes unchanged generated text, including automatic mailbox signatures, and excludes it from voice evidence. Repeated external sent samples remain cautious evidence rather than proof of human authorship. Substantive edits and output generated by another application cannot be attributed perfectly.

Consolidation recalls general facts from each relevant category and searches the entire scope for text and contact matches before applying a bounded writer input. It updates an existing concept when evidence changes, rather than appending an exhaustive mail summary. Recent evidence receives more weight. Explicit facts and instructions are retained unless corrected, forgotten or given an expiry. Old, unconfirmed, low-confidence inferred facts can stop contributing to context.

## Capture

| Source | Learning |
| --- | --- |
| Onboarding and mailbox connection | Queue separate samples of up to 50 recent received and 50 sent messages. |
| Incoming Gmail and messages sent from another client | Capture through Gmail history and recovery independently of auto-label settings. |
| Managed incoming mail | Capture during durable ingestion, including retried deliveries. |
| Thread opens and AI mail reads | Reuse fetched content, including messages already marked read. |
| Compose drafts and successful sends | Capture authored revisions and final accepted text. |
| Bulk mail actions | Persist message IDs first, then hydrate message evidence in the memory worker. |
| Label corrections and brief feedback | Learn handling preferences with the action and sender evidence. |
| User chat | Queue ordinary messages. Apply explicit additions, corrections and forgetting before the answer. |

Source keys deduplicate provider deliveries, refetches and retries. Reading the same message repeatedly does not make its claims stronger. Bootstrap state keeps separate cursors, counts and completion flags for received and sent samples. It is checkpointed and retried through scheduled mail maintenance. Settings shows scan progress and can start or retry an incomplete scan. A change of private mailbox owner starts a fresh scan for that owner and cancels the previous scan's lease.

## Initial context and further recall

Every contextual generation uses `loadAiAgentContext` from `packages/orpc/src/ai-memory.ts`. Its implementation in `ai-memory-context.ts` rechecks mailbox access and selects owned records with SQL. Cached candidate handles contain identities and scope choices, never a previously authorized copy of private facts.

The loader reserves space across task-specific categories, includes applicable instructions and exact correspondent knowledge, then fills remaining space by relevance and salience. SQL matches the complete stored collection before applying per-category, contact and lexical result limits. No model call is needed for recall. The loader owns the prompt budget, so consumers must not truncate the resulting text again.

Chat, reply suggestions, dictated-mail formatting, daily briefs, auto-labeling and natural-language mail search receive task-specific context before generation. Strict verification-code extraction, transcription and administrative generation remain evidence-only. Chat can search or page through further memories with `read_personal_context`. Live calendar questions use connected calendar reads and current event evidence, never remembered availability.

## User control and deletion

Settings offers personal and accessible-mailbox scopes, full-text search, category filtering, stable pages, direct additions, versioned edits and individual permanent deletion. Shared-mailbox readers can inspect knowledge; only managers can edit it. Mail scan progress is separate from queued learning, and model failures or insufficient balance remain visible. Manual additions and edits require neither an AI call nor an available AI balance. They work while automatic learning is paused. Explicit chat additions and edits also work while paused, but require the normal model budget.

Deleting a fact removes its content and recoverable change snapshots. Reset removes the scope's facts and history and stops its bootstrap work. Both fence in-flight plans and cancel pending older evidence. Scrubbed event-ID tombstones remain to prevent the same provider message from recreating a deleted fact. Reset does not automatically restart onboarding scans. New evidence can establish a fact again; deletion is not permanent suppression of a topic.

The worker claims evidence with a lease, rechecks scope revision, learning settings, access, event ownership and touched record versions, then commits facts and event completion together. A late worker cannot clear a newer claim. Processed or canceled payloads are scrubbed. Model failures leave no partial fact changes and retry without duplicating successful events.

## Local operation and rollout

Use `vp run dev:full` for the web and local Worker runtimes. Automatic bulk learning remains disabled locally. Run `vp run dev:trigger memory <local-user-id>` to process only that user's queued bootstrap and memory work. Use budget-limited development AI credentials. The trigger performs provider reads, not provider mutations; existing local Gmail ownership rules still apply to other background processing.

The new migration adds bootstrap state, expiring generated-text fingerprints and text/category indexes. It is additive and passes the migration safety policy. Historical vector columns and retired tables remain inert for a later contract release after older workers stop using them. The historical migration chain still includes the vector extension. The current runtime has no embedding service or embedding credential requirement. No production data cleanup or deployment is part of this PR.
